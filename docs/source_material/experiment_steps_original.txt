# 1. 先把 VTOL 基础仿真模型跑通

第一步先完全不要加 RL。

对象固定为：

\[
\boxed{\text{Lift+Cruise VTOL}}
\]

即：

- 垂直升力旋翼；
- 固定机翼；
- 前推螺旋桨；
- elevator；
- 如果做 6-DOF，再加入 aileron / rudder。

先完成三种基本状态：

\[
\text{Hover}
\]

\[
\text{Transition}
\]

\[
\text{Fixed-wing Cruise}
\]

确认传统控制器本身能够完成：

> 悬停 → 加速 → 建立机翼升力 → 减少 lift rotor thrust → 固定翼巡航。

这一步只解决：

\[
\boxed{\text{飞机模型和低层飞控本身能不能正常工作}}
\]

不涉及强化学习。

---

# 2. 建立统一的标准转换工况

先固定一个 nominal case，后面所有算法都从完全一样的初始状态出发。

例如：

\[
h_0=50\,m
\]

\[
V_{a,0}\approx0
\]

\[
\theta_0\approx0
\]

\[
\phi_0\approx0
\]

\[
v_{z,0}\approx0
\]

目标：

\[
h_d=h_0
\]

\[
V_{a,d}=V_{\rm cruise}
\]

也就是说：

> 无人机在固定高度从 hover 加速到 fixed-wing cruise。

建议整个论文都围绕这一标准任务展开，不要一会儿爬升、一会儿下降、一会儿转弯。

否则变量太多。

# 3. 标定基础空气动力学参数

这一步是为了后面的：

\[
\eta_L
\]

和：

\[
\eta_C
\]

能够计算。

至少需要得到：

\[
C_L(\alpha)
\]

以及：

\[
C_{m_{\delta_e}}
\]

或者完整一些：

\[
C_m(\alpha,\delta_e)
\]

数据来源可以是：

- 飞机模型自带气动参数；
- CFD；
- 风洞；
- 仿真扫频/扫角；
- 已知 aircraft aerodynamic database。

最终得到：

\[
\hat L_w
=
\frac12\rho V_a^2S C_L(\alpha)
\]

和 elevator control effectiveness。

你参考的 CEP 论文也是先通过 CFD 建立气动系数，再进入强化学习与控制设计，而不是直接让 RL 黑箱学习所有气动关系。

\[
\lambda=
0,0.1,0.2,\ldots,1

每一个：

\[
(V_a,\lambda)

记录：

\[

\]

\[
\alpha

\[

\[

\]

\[

\]

### 图 A

\[

# 6. 第三组 F3：正式验证 \(\eta_L\)

现在开始计算：

\[
\boxed{
\eta_L
=
\operatorname{sat}_{[0,1]}
\left(
\frac{
\frac12\rho V_a^2SC_L(\alpha)
\cos\gamma\cos\phi
}{
\hat m(g+a_{z,d})+\varepsilon
}
\right)
}
\]

对于恒高转换：

\[
a_{z,d}=0
\]

所以近似：

\[
\eta_L
\approx
\frac{
L_w\cos\gamma\cos\phi
}{
\hat mg
}
\]

实验方法：

在不同：

\[
V_a,m,\alpha,wind
\]

条件下计算：

\[
\eta_L
\]

然后观察：

\[
\eta_L
\]

与“能够安全减少 lift rotor thrust 的程度”之间是否存在明显关系。

理想结果应该类似：

\[
\eta_L\uparrow
\Rightarrow
\lambda_{\rm feasible}\uparrow
\]

# 7. 第四组 F4：验证 \(\eta_C\)

启动我们设计的：

\[
\boxed{\text{Shadow FW Pitch Controller}}
\]

让它一直计算：

\[
M_{\rm req}^{FW}
\]

但是暂时不一定完全执行。

根据：

\[
V_a,\delta_e,C_{m_{\delta_e}}
\]

计算：

\[
M_{e,\rm ava}
\]

然后计算：

\[
\eta_C
\]

重点做低速到高速扫描。

你希望看到：

\[
V_a\approx0
\Rightarrow
\eta_C\approx0
\]

随着：

\[
V_a\uparrow
\]

动态压强：

\[
\bar q\uparrow
\]

最终：

\[
\eta_C\uparrow
\]

也就是说：

> elevator 的控制能力是逐渐建立的，而不是某个空速突然从 0 变成 1。

# 8. 第五组 F5：证明 \(\eta_L+\eta_C\) 比单纯 \(V_a\) 更有效

这一组我非常建议放进论文。

构造大量随机转换状态。

每个状态给一个 candidate：

\[
\lambda
\]

然后继续仿真：

\[
T_p=1\sim3s
\]

判断：

\[
y=
\begin{cases}
1,&安全\\
0,&不安全
\end{cases}
\]

安全可以定义为没有发生：

\[
|\alpha|>\alpha_{\max}
\]

\[
|e_h|>h_{\max}
\]

\[
|q|>q_{\max}
\]

或者明显失速/掉高。

然后比较两组输入：

### Model A

\[
V_a
\]

### Model B

\[
[V_a,\eta_L,\eta_C]
\]

对“candidate \(\lambda\) 是否安全”的解释能力。

可以给：

\[
ROC-AUC
\]

或：

\[
F_1
\]

如果：

\[
AUC(V_a)
<
AUC(V_a,\eta_L,\eta_C)
\]

就形成非常强的证据：

\[
\boxed{
\eta_L,\eta_C
\text{确实提供了单一空速没有的信息}
}
\]

这比单纯画两条曲线有说服力得多。

# 11. Actor 只输出 residual

CfC Actor 输出：

\[
a_t^{RL}\in[-1,1]
\]

转换为：

\[
\Delta\lambda_t^{RL}
=
\delta_\lambda a_t^{RL}
\]

然后：

\[
\boxed{
\lambda_d
=
sat
(
\lambda_{\rm phy}
+
\Delta\lambda_t^{RL}
)
}
\]

所以整个算法学的是：

> 相对于物理先验，应该提前还是推迟卸载。

---

# 12. Safety Shield 处理候选动作

根据：

\[
V_a,\alpha,\eta_L,\eta_C,e_h,v_z
\]

计算：

\[
\lambda_{\max}^{hard}
\]

然后：

\[
\lambda_{\rm proj}
=
\min
(
\lambda_d,
\lambda_{\max}^{hard}
)
\]

再经过非对称 rate limiter：

\[
\lambda_{\rm proj}
\rightarrow
\lambda_{\rm exec}
\]

满足：

\[
\dot\lambda_{\max}^{+}
<
\dot\lambda_{\max}^{-}
\]

也就是：

> 卸载慢，恢复旋翼快。

---

# 13. 执行 VTOL 控制

根据：

\[
\lambda_{\rm exec}
\]

计算 lift rotor feed-forward：

\[
T_{L,ff}
\]

再加高度反馈：

\[
T_{L,cmd}
=
T_{L,ff}
+
T_{L,fb}
\]

前推电机仍然由：

\[
V_a\ controller
\]

控制。

而 FW/MC 姿态控制融合由：

\[
\eta_C
\]

控制，而不是直接由：

\[
\lambda
\]

控制。

这样每个模块职责非常清晰。
